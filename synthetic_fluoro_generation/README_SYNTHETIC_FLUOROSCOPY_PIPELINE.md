# Synthetic Brain-Vessel Fluoroscopy Generation

This guide summarises the complete workflow for generating synthetic head fluoroscopy images with enhanced cerebral vessels.

All project scripts are stored in:

```text
synthetic_fluoro_generation/
```

The pipeline combines CT/CTA preprocessing, brain-mask generation, rigid registration, TOPBrain vessel segmentation, vessel enhancement, and projection with nanoDRR or DeepDRR.

> **Pipeline status:** Some scripts are still being developed. The workflow below is the intended structure and can be updated as the pipeline changes.

## Workflow summary

| Step | Process | Main output |
|---:|---|---|
| 1 | Reorient CT and CTA to LPS | LPS CT and CTA |
| 2 | Generate brain masks with TotalSegmentator | CT and CTA brain masks |
| 3 | Rigidly align the CTA to the common template | Template-aligned CTA |
| 4 | Rigidly register the CT to the aligned CTA | Registered CT |
| 5 | Resample and crop every image onto the template grid | Ready CT, CTA, and masks |
| 6 | Segment cerebral vessels with TOPBrain KDH | Vessel label map |
| 7 | Convert and validate the vessel prediction | Ready vessel-mask NIfTI |
| 8 | Enhance vessel-labelled voxels in the CT | Vessel-enhanced CT |
| 9 | Generate nanoDRR projections | nanoDRR fluoroscopy images |
| 10 | Generate DeepDRR projections | DeepDRR fluoroscopy images |

## One-time setup

### 1. Prepare the common CTA template

Select one good-quality CTA to act as the fixed template. This first case should have:

- Complete brain coverage
- A neutral head orientation
- Minimal head tilt or rotation
- A reliable TotalSegmentator brain mask
- A field of view large enough for the required anatomy

Orient the template so that it represents a head-first, supine patient. Save:

```text
template_CTA.nii.gz
template_brain_mask.nii.gz
```

The template defines the common anatomical orientation, output grid, crop, and projection isocentre. The first/template case does not need to be registered to itself.

### 2. Prepare the required environments

The complete workflow uses several environments because its tools have different dependencies.

| Stage | Platform/environment |
|---|---|
| LPS reorientation | Windows Python or `reorient_env` |
| TotalSegmentator | `totalseg_env` |
| Template and CT registration | Windows `itk_elastix_env` |
| Resampling and cropping | Windows `itk_elastix_env` |
| TOPBrain | CREATE cluster with Singularity and an A40 GPU |
| Vessel enhancement | Windows Python with SimpleITK/NumPy |
| nanoDRR | Windows nanoDRR/PyTorch installation |
| DeepDRR | Ubuntu/WSL with `deepdrr` Conda environment |

### 3. Prepare the vessel mapping

Keep the vessel label mapping in the project folder:

```text
vessel_mapping.json
```

This is a fixed metadata file mapping vessel names to integer label IDs. It is not generated by TOPBrain.

## Per-patient workflow

Create a separate working directory for every patient. Keep the original images unchanged.

Suggested naming:

```text
<case_id>/
├── 1_original_CT.nii.gz
├── 2_original_CTA.nii.gz
├── 3_CT_LPS.nii.gz
├── 4_CTA_LPS.nii.gz
├── 5_CT_LPS_brain_mask.nii.gz
├── 6_CTA_LPS_brain_mask.nii.gz
├── 7_Aligned_CTA.nii.gz
├── 8_Registered_CT.nii.gz
├── 9_Ready_CT.nii.gz
├── 10_Ready_CTA.nii.gz
├── 11_Ready_CT_brain_mask.nii.gz
├── 12_Ready_CTA_brain_mask.nii.gz
├── 13_Labeled_vessel_mask.nii.gz
└── 15_Enhanced_CT.nii.gz
```

### Step 1: Reorient the CT and CTA to LPS

Run:

```text
1_reorient_nii.py
```

Inputs:

```text
1_original_CT.nii.gz
2_original_CTA.nii.gz
```

Outputs:

```text
3_CT_LPS.nii.gz
4_CTA_LPS.nii.gz
```

The script should process the CT and CTA together and report their orientations before and after reorientation.

Check that:

- Both outputs report LPS orientation.
- Neither image is left-right reversed.
- Image intensities have not changed unexpectedly.

### Step 2: Generate CT and CTA brain masks

Activate the TotalSegmentator environment:

```bash
conda activate totalseg_env
```

Run TotalSegmentator separately on:

```text
3_CT_LPS.nii.gz
4_CTA_LPS.nii.gz
```

Retain the brain masks as:

```text
5_CT_LPS_brain_mask.nii.gz
6_CTA_LPS_brain_mask.nii.gz
```

Before continuing, open each image and mask together and confirm that the mask correctly covers the brain.

### Step 3: Align the CTA to the common template

Run:

```text
3_align_cta_to_template.py
```

Use:

```text
Fixed image:    template_CTA.nii.gz
Fixed mask:     template_brain_mask.nii.gz
Moving image:   4_CTA_LPS.nii.gz
Moving mask:    6_CTA_LPS_brain_mask.nii.gz
Transform:      rigid only
```

Outputs:

```text
7_Aligned_CTA.nii.gz
7_Aligned_CTA_brain_mask.nii.gz
CTA_to_template_transform.txt
```

For the template patient, copy the template CTA and mask into the expected output names instead of registering the template to itself.

Check that:

- The midsagittal plane agrees with the template.
- The superior-inferior and anterior-posterior orientations agree.
- No left-right reversal has occurred.
- The transformed brain mask overlaps the aligned CTA.

### Step 4: Register the CT to the aligned CTA

Activate the registration environment:

```powershell
.\itk_elastix_env\Scripts\Activate.ps1
```

Run:

```text
4_register_ct_to_cta_elastix.py
```

Use:

```text
Fixed image:    7_Aligned_CTA.nii.gz
Fixed mask:     7_Aligned_CTA_brain_mask.nii.gz
Moving image:   3_CT_LPS.nii.gz
Moving mask:    5_CT_LPS_brain_mask.nii.gz
Transform:      rigid only
Outside value:  -1024 HU
```

Use the CTA-to-template transformation to initialise this registration where possible.

Outputs:

```text
8_Registered_CT.nii.gz
8_Registered_CT_brain_mask.nii.gz
CT_to_template_transform.txt
```

Inspect the CT and CTA together. Do not continue if there are double skull contours, obvious rotation errors, or non-overlapping anatomy.

### Step 5: Resample and crop onto the template grid

Run:

```text
5_resample_and_crop_to_template.py
```

Resample the aligned CTA, registered CT, and transformed masks onto one fixed template grid. Apply the same template crop to every patient.

Use:

- Linear interpolation for CT and CTA images.
- Nearest-neighbour interpolation for all masks.
- `-1024 HU` outside the transformed CT.

Outputs:

```text
9_Ready_CT.nii.gz
10_Ready_CTA.nii.gz
11_Ready_CT_brain_mask.nii.gz
12_Ready_CTA_brain_mask.nii.gz
CT_coverage_mask.nii.gz
```

Confirm that all outputs have the intended template dimensions, spacing, origin, and direction.

### Step 6: Run TOPBrain KDH on CREATE

Upload the prepared CTA to the CREATE cluster and run the TOPBrain KDH model using the established Singularity/SLURM workflow.

Detailed CREATE instructions are provided in:

```text
README_CREATE_TOPBRAIN.md
```

TOPBrain may initially produce an `.mha` prediction. Download the completed prediction from CREATE.

> Establish model performance using a full-field LPS CTA before replacing it with a tightly cropped input. Removing head or neck context may affect segmentation performance.

### Step 7: Convert and validate the vessel prediction

Convert the TOPBrain `.mha` prediction to NIfTI if required.

Save the final mask as:

```text
13_Labeled_vessel_mask.nii.gz
```

If the prediction does not already match the prepared CTA grid, resample it onto `10_Ready_CTA.nii.gz` using nearest-neighbour interpolation.

Confirm that:

- The mask contains integer label IDs.
- Vessel labels are anatomically aligned with the CTA.
- No left-right reversal or spatial shift has occurred.
- The vessel mask and `9_Ready_CT.nii.gz` have the same shape and physical grid.

### Step 8: Enhance the vessels in the registered CT

Run:

```text
7_prepare_vessel_enhanced_ct.py
```

Inputs:

```text
9_Ready_CT.nii.gz
13_Labeled_vessel_mask.nii.gz
vessel_mapping.json
```

Example PowerShell command:

```powershell
python 7_prepare_vessel_enhanced_ct.py `
  --ct "9_Ready_CT.nii.gz" `
  --labels "13_Labeled_vessel_mask.nii.gz" `
  --mapping "vessel_mapping.json" `
  --mode floor `
  --value 500 `
  --output "15_Enhanced_CT.nii.gz"
```

The `floor` mode imposes a minimum HU value on selected vessel voxels. The `add` mode adds a fixed HU increment instead.

Inspect the enhanced CT together with the vessel mask before generating projections.

### Step 9: Generate nanoDRR fluoroscopy images

Run nanoDRR on Windows:

```text
8_1_fluoroscopy_sim_nanodrr.py
```

Inputs:

```text
15_Enhanced_CT.nii.gz
13_Labeled_vessel_mask.nii.gz
vessel_mapping.json
```

Example:

```powershell
python 8_1_fluoroscopy_sim_nanodrr.py `
  --ct "15_Enhanced_CT.nii.gz" `
  --labels "13_Labeled_vessel_mask.nii.gz" `
  --mapping "vessel_mapping.json"
```

In the simulator:

1. Confirm that the enhanced CT is visible.
2. Enable the segmentation overlay.
3. Select the required vessel labels.
4. Choose the required projection angle.
5. Set the agreed detector geometry.
6. Save the displayed image as PNG.

The nanoDRR label-overlay and common-angle implementation are still being refined.

### Step 10: Generate DeepDRR fluoroscopy images

Copy or make the enhanced CT, vessel mask, and mapping file accessible inside Ubuntu/WSL.

Activate the DeepDRR environment:

```bash
conda activate deepdrr
```

Run:

```bash
python 8_2_fluoroscopy_sim_deepdrr.py \
  --ct "/path/to/15_Enhanced_CT.nii.gz" \
  --labels "/path/to/13_Labeled_vessel_mask.nii.gz" \
  --mapping "/path/to/vessel_mapping.json"
```

Use Linux paths inside WSL rather than Windows UNC paths.

In the simulator:

1. Confirm that the enhanced CT is visible.
2. Enable the segmentation overlay if required.
3. Select the same vessel labels used for nanoDRR.
4. Use the same projection view and detector geometry.
5. Save the displayed image as PNG.

## Matched projection settings

For a fair nanoDRR/DeepDRR comparison, use the same:

- Input enhanced CT
- Vessel label mask
- Visible vessel labels
- Anatomical projection direction
- Projection isocentre
- Source-to-isocentre distance
- Source-to-detector distance
- Detector dimensions
- Detector pixel spacing
- Output image size
- Display inversion state

Initial comparison settings:

```text
SID:             850 mm
SDD:             1020 mm
Detector:        512 x 512 pixels
Pixel spacing:   0.6 mm
```

Once the camera-coordinate corrections have been applied to both simulators, standard presets should include AP, PA, left lateral, and right lateral views.

## Final outputs

Save images using names that record the case, renderer, view, and enhancement setting. For example:

```text
<case_id>_nanodrr_AP_floor500HU.png
<case_id>_deepdrr_AP_floor500HU.png
<case_id>_nanodrr_left-lateral_floor500HU.png
<case_id>_deepdrr_left-lateral_floor500HU.png
```

For each experiment, record:

- Patient/case ID
- CT and CTA input filenames
- Template version
- Vessel-segmentation model
- Selected vessel labels
- Enhancement mode and HU value
- Renderer
- Projection view
- SID and SDD
- Detector dimensions and pixel spacing

## Quality-control checklist

Do not generate final comparison images until all of the following are true:

- [ ] CT and CTA are in the expected orientation.
- [ ] Brain masks align with their source images.
- [ ] CTA is rigidly aligned to the common template.
- [ ] CT is rigidly aligned to the CTA.
- [ ] No skull double contours are visible.
- [ ] All prepared images and masks use the same grid.
- [ ] Masks were resampled using nearest-neighbour interpolation.
- [ ] The vessel mask contains integer label IDs.
- [ ] The vessel mask overlaps the cerebral vessels in the CTA.
- [ ] The enhanced CT contains the expected modified vessel voxels.
- [ ] nanoDRR and DeepDRR use matched projection geometry.
